# 刀尖热误差间歇测量与六路冷却数据采集方案 V1

日期：2026-10-10；本次补充：已读取 MATLAB 阀门控制程序。  
阶段：采集与试验方案草案。六路冷却位置由用户后续填写；本阶段不修改或连接现场控制设备。

## 1. 已确认的实验条件

- 机床运行时，测量球离开三个电涡流探头；必须暂停并返回固定检测位，才能获得有效的 XYZ 相对热漂移。
- 已有 18 路温度采集、三探头位移采集和 XYZ 标定矩阵。
- 六路球阀可独立调节，统一编号 U1—U6。每路具体冷却位置不影响采集字段设计。
- 现有程序设置：连续采集每 2 秒一轮，返回检测位后等待 5 秒，再按 2 秒间隔采集 10 个点。
- 六路阀门由电脑通过 MATLAB 下发。所提供程序使用 Modbus RTU，阀门串口 9600 baud、8N1；六个从站为 1、2、4、5、7、8，写入保持寄存器 2。
- 阀门指令乘 100 后取整发送，原程序将发送值限制为 0—6000，计算指令限制为 0—60。界面显示百分比，注释写 60°，实际单位待用户按仪表或说明书确认。
- 所提供程序读取三路水冷机水箱温度，但未读取阀门实际位置。缺少反馈的量保持缺失；水箱温度与冷却板入口水温分别定义。
- 第一阶段目标是取得可追溯的“阀门动作—温度—固定检测位热漂移”数据。能否有效抑制漂移，由后续响应试验和对比试验验证。

## 2. 推荐的推进方式

| 方式 | 工作内容 | 适用阶段 |
| --- | --- | --- |
| MATLAB 下发预设开度并自动记录 | 六路分别设定，自动保存发送值、发送时间、通信结果；连续采温度并定点测热漂移 | 推荐作为第一版，采集基线与单路冷却响应 |
| 定点热漂移反馈更新开度 | 有效 XYZ 测量完成后，由控制策略决定是否更新六路开度 | 获得初步冷却响应后 |
| 运行期间估计热漂移，再持续更新阀门 | 用温度及工况建立估计模型，定点实测用于校正 | 后续扩展，需要额外辨识和验证 |

运行期间没有新的有效热漂移实测值。第一版采集按操作者的预设试验指令调阀，保持已经下发的设定直至下一次试验动作。未来采用定点反馈时，仅在有效测量完成后决定是否更新开度，两次更新之间保持上次设定。控制更新周期需根据测量间隔和冷却响应确定。

### 2.2 当前记录方式对实验辨识的限制

- 当前 ADRC 的反馈是四个结构温度，目标是温度；尚未使用 XYZ 热漂移。第一版采用六路独立预设开度模式，为后续热漂移控制取得数据。
- 原程序 U1/U2 都使用 T1，U5/U6 都使用 T4，并采用相同初始状态和参数；它们不会提供六路独立的试验激励。单路辨识时需由预设试验模式分别指定每一路。
- 六路阀门写入均在空 catch 中忽略失败，之后仍把计算出的 u_cmd 写入日志。新数据必须分别保存计算/设定指令、编码发送值、每路通信结果和可获取的实际反馈。
- 机床温度、水箱温度读取失败时会使用旧值，缺少有效性和旧值龄期。新采集记录保留缺失或注明旧值来源与时间，不能当成新的成功读取。
- 控制程序以日志长度生成时间，V3 以成功样本序号乘 2 生成时间。统一采用实际经过时间，并保留计划周期、读取起止时间和失败记录。
- 原控制循环计划每 1 秒执行，V3 计划每 2 秒执行。综合采集暂按 2 秒安排，验证整轮读取耗时；若将旧 ADRC 保留为对照模式，必须保持其步长与实际执行周期一致，不能直接将 h=1 的计算搬到 2 秒周期。
- 原控制程序会依据结构温度自动改变水冷机启停。固定开度与单路辨识试验应预先明确水冷机工作方式，保存其启停指令与发送结果，避免未记录的供水动作影响判断。

## 3. 一轮实验的操作流程

1. **准备。** 固定检测位置、返回路线、运行程序和供水设定；登记六路初始开度，保存本轮实验编号和标定版本。
2. **冷态测量。** 测量球置于检测位，确认静止与探头在有效范围内。等待并采集窗口，保存本轮冷态探头基准及温度、开度。
3. **运行。** 登记恢复运行时刻；连续记录温度、探头原始值及设备状态。测量球离开后，探头数据标记为非有效热漂移测量。
4. **暂停、返回、到位。** 分别登记开始暂停、开始返回和检测位到位时刻。没有机床到位接口时，由操作者点击到位标记，不能从探头数值单独推断到位。
5. **稳定与测量。** 暂沿用 5 秒等待和 10 点平均，保存窗口原始点、实际时间及读取耗时。5 秒是现有配置，是否足够需由静止和重复返回试验核验。
6. **计算并保存。** 有效窗口通过检查后计算 XYZ；失败的窗口也保存原始数据和失败原因，XYZ 有效输出保持缺失。
7. **登记冷却动作并继续运行。** 若按试验计划调整阀门，记录每个支路的调整前后开度和实际操作时间；记录恢复运行时刻。没有调整也保留当前开度状态。

整轮实验沿用同一冷态基准。再次归零应结束当前实验编号并建立新的一轮，避免热漂移被清零。

热误差计算：  
**XYZ = C ×（本次窗口三探头平均值 − 本轮冷态三探头基准）**。  
C 是已标定的三探头到 XYZ 转换矩阵。标定文件中的标定零位与本轮实验冷态基准应分别保存。

## 4. 数据结构

建议最终按一个实验编号组织成四类记录；Excel 可以对应四张表。运行时先追加保存，实验结束再整理导出，减少中断导致整轮数据丢失的可能。

### 4.1 实验设置

- 实验编号、日期、操作者、运行程序编号。
- 固定检测位置及机床坐标、返回路线编号；测量球代表点与实际刀尖的几何关系说明。
- 采集设定周期、等待时间、目标窗口点数。
- 三探头标定矩阵、标定文件标识、标定误差记录、本轮冷态探头基准。
- 阀门编号 U1—U6、各路冷却位置、初始开度和记录来源。
- 供水温度设定及实际读取能力。
- 探头有效范围、单位和判定依据。现有程序的 ±100 μm 配置应结合仪表与标定范围核实。

冷却位置留作用户配置，不按床身、立柱、横梁自动分配：
U1：________；U2：________；U3：________；U4：________；U5：________；U6：________。

### 4.2 连续采集数据

| 字段 | 单位或类型 | 记录要求 |
| --- | --- | --- |
| 实验编号、采样序号 | 标识 | 序号与时间分开 |
| 实际采集时间、实际经过时间 | 日期时间、s | 实验开始后用单调计时记录经过时间；保留计划采样时间作比较 |
| 本轮读取开始、结束、耗时 | s | 多个 Modbus 仪表顺序读取，不能宣称硬件同时采样 |
| T1—T18 | ℃ | 沿用现有测点名称；保存读数有效性 |
| P1—P3 | μm | 保存原始仪表位移，不预先删除运动期间读数 |
| 机床阶段 | 分类 | 运行、返回、稳定等待、窗口测量、测量完成、停止 |
| 位移有效性及原因 | 分类 | 到位未确认、运动中、超范围、通信失败等分别标记 |
| U1—U6 最近登记的指令或设定开度 | 单位待确认 | 电脑下发；每路保留原始指令、编码值及最近发送时间、发送结果 |
| U1—U6 实际反馈开度 | 单位待确认 | 原代码尚未读取；设备可读取时才填入，同时保存读取时间 |
| 供水设定、实际供水温度 | ℃ | 有数据时记录；不可获取时缺失 |
| WC1—WC3 水箱温度、启停指令及结果 | ℃、0/1、状态 | 沿用现有水箱温度读取接口；读取失败保留标记；启停指令与运行反馈区分 |
| 数据来源、通信状态 | 分类 | 真实或模拟逐条标记；失败记录保留，不压缩时间轴 |

在连续行中展示最近开度指令时，要携带其发送时间与发送结果。这是历史指令的延续，不是新的实际阀位测量；发送失败不能将该目标指令当作已执行的阀位。

### 4.3 定点热误差样本与窗口点

| 字段 | 记录要求 |
| --- | --- |
| 样本编号、类型 | 冷态基准或热误差测量；关联原始窗口点 |
| 到位时刻、窗口开始、窗口结束 | 保存实际发生时间 |
| 窗口代表时刻、计算完成时刻 | 均值对应窗口代表时刻；反馈只能在计算完成后使用 |
| 有效点数、P1—P3 平均值 | 检查读数有限、在有效范围内、没有丢失点 |
| XYZ 平均值、XYZ 窗口标准差 | 分别描述窗口均值和窗口内波动 |
| 窗口有效性、失败原因 | 无效窗口不输出有效热漂移，不能填零 |
| 最近一次有效样本时间、样本龄期 | 不把旧样本当成当前的新实测值 |
| 对应的阀门状态及事件编号 | 能追溯从前次测量至本次测量之间的全部阀门动作 |

10 个点以 2 秒间隔采集时，首末点理论间隔为 18 秒；实际窗口起止时间以记录为准。窗口均值、有效点数和标准差应由保存的原始窗口点重算得到。

窗口有效性要求：测量球处于固定检测位、机床静止、稳定等待完成、三个探头均在有效范围内、读取成功且目标有效点数齐全。波动阈值需经静止测试确定；超出范围后按失败原因保存并重测，不能自动使用该窗口控制。

窗口标准差不是全部测量不确定度；标定误差和重复返回误差应另行评估。程序的探头有效范围作用于探头读数，不应直接套用于 XYZ 转换结果或探头相对冷态变化量。

### 4.4 操作事件

每个事件保存：实验编号、事件编号、实际时间、动作、支路编号、旧值、新值、记录来源、操作结果和备注。阀门事件另存从站地址、MATLAB 寄存器参数、编码发送值、发送起止时间、成功/失败/超时结果；实际阀位反馈在有依据的接口提供后再增加。

事件包括：
- 实验开始、冷态基准建立；
- 暂停、开始返回、检测位到位、测量开始/完成、恢复运行；
- 各路阀门设定变化、电脑指令发送、设备确认或反馈；
- 供水设定变化、运行程序变化、异常与实验结束。

六路阀门若依次调整，每一路分别登记实际时间，不能强行记作同一时刻。

## 5. 第一阶段试验

### A. 验证测量重复性

先在固定位置静止测量数个窗口，再重复相同的离开—返回路线。记录 XYZ 均值、窗口波动及每次暂停时间，评估传感器波动与重复返回误差。窗口内稳定不代表返回位置完全一致。

### B. 取得固定开度基线

选择已确认可运行的六路基准开度和供水设定，整轮保持该设定，执行固定运行—返回—测量流程。第一轮可试用每运行 5 分钟返回测量的节拍，作为探索性设置；实际可行性、暂停占比及热响应速度决定后续调整。该间隔不是已经验证的最终控制周期。

记录启动、暂停和供水变化，保持返回路线和等待/测量步骤一致。冷态是热漂移参照；控制目标容差应结合测量能力和试验目标确定，不承诺达到绝对零漂移。

### C. 初步辨识单路作用

基线可复现后，选择一路 Uj，在已确认的工作范围内做小幅开度变化，其余五路维持基准设定，继续相同运行和检测节拍。开度水平、变化幅度与保持时长由阀门工作范围及先导响应确定，不统一假设 0%、50% 或 100% 可用。

保留变化前、变化中、恢复后的数据；后续重复并改变输入水平，验证结果。先导试验用于判断作用方向、可观测幅度和大致延迟，不能单凭一次阶跃建立完整六输入三输出模型。环境和暂停历史作为辅助记录，固定开度基线用于区分自然热漂移与阀门变化的影响。

## 6. 现有 MATLAB 程序的后续改造范围

1. 六路冷却位置留作用户填写；沿用已核对的阀门从站地址、寄存器参数和编码，实际串口与开度单位放入配置。
2. 增加实际采集时间、读取耗时、失败记录及数据来源标记；保留原始采样序号。
3. 增加运行阶段、到位标记和阀门变化事件登记。
4. 保留现有标定矩阵转换及冷态测量，增加窗口有效性、样本龄期及原始窗口点保存。
5. 真实采集读取失败时记录缺失/故障；模拟模式必须明确启用并隔离，模拟数据不用于现场反馈。
6. 追加保存采集与事件数据，结束时统一导出。本阶段优先完成记录链路。
7. 第一版加入六路独立预设指令下发与发送结果记录；实际阀位读取地址待有设备依据后填写。共享串口的读写采用顺序调度，不由多个独立回调同时操作。
8. 主界面拟提供“开始采集、建立冷态基准、机床运行、开始返回、检测位到位/开始测量、恢复运行、发送六路设定、结束实验”等操作；每个动作同步生成事件。只有明确的阀门发送动作负责写入，后台采集不调用温度 ADRC 改写试验设定。
9. 暂以两个现有程序的通信调用为驱动依据，并用统一实验计时和记录层组织它们；不同时启动两个会管理相同串口或写入同一阀门的原 GUI。

上述内容是拟改造范围，尚未修改上传的 MATLAB 文件，也未进行现场通信或冷却控制验证。

## 7. 采集方案验收与下一步

第一版采集应能做到：
- 每个有效 XYZ 样本可定位到原始窗口点、本轮冷态基准和标定矩阵。
- 每次阀门调整、暂停及恢复运行均有实际时间，能重建两次测量之间的输入和工况历史。
- 球离开探头、超范围、通信失败、模拟数据均有明确标记。
- 程序延迟或漏采时，实际时间不会被“序号 × 2 秒”掩盖。
- 缺少阀位反馈或供水温度时，明确显示未获取，不用指令冒充实测值。
- 记录中断后，已保存的数据仍可恢复；原始上传文件不被覆盖。

下一项需确认：原程序的 0—60 代表百分比开度还是角度。现有界面与注释存在歧义，应按仪表显示或设备说明书确认。通路对应、现场 COM 名称、阀门实际位置反馈地址可继续作为配置项后续填写。
