# 单总线现场接入核对

此表用于准备真实通信适配器，当前不会被程序加载为指令。

| 项目 | 要取得的依据 | 接入前结果 |
|---|---|---|
| 唯一主站 | 同一条 RS485 只有一个端口所有者，旧 GUI 不同时抢口 | 待核实 |
| 地址唯一 | 全部温度、探头、阀门、冷水机从站地址清单及设备实测 | 待核实 |
| 通信一致 | 波特率、校验、停止位、总线极性、终端与接地 | 待核实 |
| 读数解码 | 功能码、寄存器是否从 0 开始、类型、字节序、缩放、单位 | 待核实 |
| 温度对应 | 18 测点身份，环境 T5、主轴 T18，与最新程序一致 | 待核实 |
| 探头换算 | 三通道身份、有效范围、符号、实际工作间隙下的 3×3 标定与版本 | 待核实 |
| 六支路输入 | A1/A2/B1/B2/C1/C2 指令和反馈，实际流量与水温，人工数据来源 | 待核实 |
| 共用水泵 | 泵、冷水机与支路组合的运行约束，启停动作和反馈 | 待核实 |
| 异常处理 | 超时、有限重试、错误标记、断线后的真实设备状态和现场恢复操作 | 待核实 |
| 回测流程 | 停转、固定点同向到位、独立角向复位、等待与窗口参数 | 待核实 |

历史代码提示温度从站 1/2/3，探头 5/6/7；水冷旧代码出现 1/2/4/5/7/8。这些只作查线索，不能作为已验证配置。历史程序 COM 口与波特率不一致。先逐设备只读核实，再确认写指令的范围、量纲、反馈和失效动作，最后通过同一队列集成。

现场真实采集与模拟试跑使用不同目录和明确模式。通信错误保留 NaN/空白与原因；不得用模拟读数补缺失。没有可读实际流量/水温时，采用带时间和来源的人工记录，不把阀门指令当成实际冷却输入。

正式对照前冻结标定、位姿、加载、初始热状态、各组合冷却输入和共同评价时段。当前 prototype 只是操作流程验证，不能直接进入真实阀门闭环。
