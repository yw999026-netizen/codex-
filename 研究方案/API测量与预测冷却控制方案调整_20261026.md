## 2. G2 损坏与模型点定义

### 2.1 当前可以和不可以测什么

用户确认损坏的是下层 G2。建模手册定义 G1＝X2、G2＝Y2、G3＝Z、G4＝X1、G5＝Y1，并给出：

```text
DX = X1 - Lp × (X2 - X1) / Ls
DY = Y1 - Lp × (Y2 - Y1) / Ls
DZ = Z
```

上下两路 Y 读数用于区分 Y 向平移与倾斜引起的差异。G2 缺失后，任意高度处的 Y 位移通常不能唯一求得。软件显示一个数值并不证明该换算有效；不能将坏通道置零、复制 G5 或用回归补值后声称仍为五点实测。

**正式主方案：修复或配套更换 G2，并核对标定后，再进行量棒端部等效刀尖的三维比较和贡献计算。** 替换探头需确认与控制箱和标定文件匹配。

修复前可做静止采集、温度导出、返回路线及重复性预试验。若实测确认 G4、G5 位于同一参考截面，且 G3 的轴向读数满足该装置的换算假设，可将目标限定为该截面的轴心位置，取 Lp＝0，则模型约定下 DX＝X1、DY＝Y1、DZ＝Z。这是指定截面的受限三向测量，不包含 Y 向倾斜，也不等于另一高度的量棒端点位移。

Lp＝0 的几何简化不保证 SpindleModel 能接受损坏通道。缺失值参与软件计算、软件要求完整五列等行为均未验证；若采用该受限方案，需在明确的后处理中只用有效通道计算，标记范围和单位。

### 2.2 Lp 的建议定义

建议将量棒自由端端面中心作为等效刀尖候选点 P；装夹净空和实际研究目标允许后固定采用。若真实刀具伸出长度不同，则明确研究对象为该等效点，不能直接称为任意刀具实际刀尖。

Lp 是 P 相对 G4 参考高度的有符号轴向距离，按手册上下定义，上方为正、下方为负，单位 mm。举例：若 P 确实位于 G4 下方 80 mm，则 Lp＝−80 mm；80 mm 仅为说明符号的例子，不是推荐尺寸。应现场测量、画出通道与轴向示意并保存尺寸，不能从上传图片推定间距或方向。

量棒整体不是一个模型点。其材料、热膨胀、装夹热漂移及与主轴的连接都进入测量误差评估；量棒温度变化不能自动当作机床结构位移扣除。

### 2.3 软件能做哪些工作

Spindle Measurement System 负责配套系统采集与分析；SpindleModel 按手册中的通道关系和 Lp 换算目标点位移并建模。`.cnf` 配套系数、探头编号及标定有效性需要核查，软件不会自动识别探头被换位、轴方向错误或量棒端点位置。

Ls 在建模手册中被称为固定参数，而采集界面有 `S1-S4 Space` 字段。应核对当前版本的实际配置与两层间距一致，不能未经验证认为采集文件会正确更新模型软件内部间距。局部小位移、方向符号、重复返回及温漂仍需验证。

## 3. 运动发热影响与冷却抑制贡献分开研究

X、Y、Z 单轴和联动试验可以比较不同运动激励下的温度与等效刀尖漂移。它们并不分别对应床身、立柱、横梁：一个轴运行可加热电机、丝杠、螺母、轴承及导轨，热量再经结构传播。

因此，只有 X、Y、Z、XYZ 四组结果时，不能唯一求出三个结构区域各自的物理发热贡献百分比，也不能默认三单轴位移之和等于联动位移。若要评价“各部分产生热对刀尖误差的权重”，须先定义部分是运动轴、热源还是结构区域，并增加可辨识的热源/温度场模型、独立激励或经验证的热—结构仿真。相关系数或温度回归系数不能直接替代物理贡献。

推荐分两阶段：

1. **运动激励筛选：** 主轴始终停转，在可比初态和固定冷却条件（先用无分区水冷）下比较 X、Y、Z 和 XYZ；记录真实速度、行程、运行占空比及驱动差异，报告各自综合热响应，不强行分配结构权重。
2. **冷却归因主实验：** 根据第一阶段的代表性、热位移可分辨性和实际研究工况选择一种固定运动程序。所有 0、A、B、C、AB、AC、BC、ABC 使用完全相同的运动与回测规则、评价时段和支路开启参数。

沿用 A＝床身、B＝立柱、C＝横梁。Shapley 对八组合结果分配的是“冷却这些区域对总抑制效果的贡献”，依赖工况、流量、水温和评价指标；它不能倒推成该部件原始产热份额。原方案的 ANSYS 筛选、全因子主效应/交互及不确定性分析继续保留。

若一个固定运动工况下每组合做 3 次独立重复，八组合需要 24 个完整热循环；若四种运动都做八组合及 3 次重复，则为 96 个循环。3 次仅为先导起点，正式次数由波动与精度目标决定。一天一个循环时至少对应同等数量的实验日，还需预留恢复与故障时间。

## 4. 回测间隔、停留时间与一日一循环

### 4.1 回测规则的选择

“无规定要求”允许设计节拍，但正式比较时不能随意改变。先在无水冷先导实验中采用候选节拍，例如运行初期及工况切换附近每 5—10 min 回测、后段每 15—20 min 回测；这些数值仅是可尝试的起点，应结合实际返回耗时和变化速度调整。

选择依据包括：相邻回测间的位移变化是否过大、能否识别峰值和转折、返回造成的暂停占比，以及定位和等待成本。可用先导数据对比不同抽样节拍下的曲线/指标偏差，给出可接受的时间分辨率。正式八组合使用统一冻结的分段节拍，不能只为效果差的组增加采样或按各组自身“看起来稳定”改变窗口。

**停留时间取达到测量要求的最短值。** 在冷态与代表性热态返回后连续记录，比较不同等待和平均窗口的均值偏差、标准差及缓慢变化。将要求与最小关心热位移和测量不确定度关联；样本自相关存在时，增加点数的效果不能直接按独立样本估计。

可从旧方案的等待 5 s、2 s 间隔采 10 点开始探索。10 点首末相隔 18 s，若第一点在等待结束时采得，则到位后的等待加窗口跨度约 23 s，另加通信和执行开销；这是候选设置，需 API 实际采样支持并经验证。若不足以稳定则延长；只有缩短后偏差仍可接受才减少。记录整个退出、运行、返回及停留过程，不仅记录窗口时间。

### 4.2 日间与夜间安排

采用相对时间安排，避免以固定钟点掩盖未恢复的初始状态。先导可考虑日间约 6—8 h 运行、夜间约 12—16 h 静止冷却观测；具体时长须根据现有数据和恢复速度选择，冻结后所有组合保持共同评价时段。时间到而温度/位移仍在变化时，应如实说明未稳定。

| 阶段 | 操作与记录 |
|---|---|
| 当日准备 | 检查设备与时间同步，按关键结构相对环境温差、变化率等判据确认可比初态；记录真实初值 |
| 冷态基准 | 分区水冷尚未施加到结构，测点静止保存统一初始位移与温度 |
| 日间运行 | 设定本组冷却组合，按固定时序开始同一运动程序，执行统一回测节拍 |
| 停机转换 | 分别记录最后停止进给、返回、到位、第一段有效静止数据及冷却切换时刻 |
| 夜间观测 | 保持测量位姿和主轴角向位置，连续记录位移与温度，避免为取样反复运动 |
| 次日评估 | 检查残余位移、关键温度及其变化率；未达到初态恢复条件则继续恢复或调整实验日期 |

长时夜间记录应先验证文件时长限制、软件分段和跨文件基准连续性。人为设置的午夜、文件切换或软件重启均不能成为新零点。夜间电源、采集和冷却状态应有可追溯记录。

## 5. 冷态基准、预冷及夜间冷却策略建议

**正式八组合建议先不单列预冷阶段。** 各组在可比的无分区预冷初态下，先记录基准，再施加本组冷却并开始运行；两者采用相同的启动顺序与固定时间关系，分别记录实际时刻。这样评价包含冷却刚开始引起的结构位移，避免预冷后归零把这一变化抹掉。

入口水温/供水准备条件需要一致；若设备能够在不向机床结构施加分区冷却的条件下稳定供水，可提前准备，具体方式按设备能力确认。环境与关键结构初态的可比性不能仅靠“都停了一夜”保证。

**夜间主方案建议在停止运行后统一停止分区主动冷却，观测共同边界条件下的自然恢复。** 各组合保留日间冷却造成的不同热历史，原有其他冷却设备、泵及残余流量状态统一并记录。这样可比较运行后的残余漂移、回零过程和可能反向漂移。

如果还需要研究停机后继续水冷能否加快恢复，可另设“保持原组合冷却”试验，并单独报告；不能将有的组继续水冷、有的组停水而未标注地合并成同一种恢复过程。将来验证控制策略时，可另外定义包括停机后主动调节的完整控制周期，与相应对照保持一致。

上述策略是本轮提出的主方案建议，尚未操作硬件或通过实验证明优于其他策略。初态接受范围、供水水平与允许偏差需由先导试验补齐。

## 6. 三维指标与冷却下降过程

始终保存带符号向量 e(t)＝[ΔX, ΔY, ΔZ]，以同一冷态为基准。综合幅值为 r(t)＝sqrt(ΔX²＋ΔY²＋ΔZ²)，评价目标可以兼顾三向，但控制器仍需要方向和符号。

保留原方案的三维 RMS 为主要指标类别，建议预先指定日间共同运行时段的三维窗口 RMS 为主指标，夜间固定共同冷却时段 RMS 为关键次指标；两阶段分别报告，避免通过延长夜间记录稀释日间误差。若选择整周期 RMS 为主指标，须在正式试验前改为所有组统一的阶段时长和时间权重。

运行期仍是间歇实测；夜间连续数据不能直接与稀疏日间数据按行等权平均。使用统一代表时间窗或预先规定的时间积分/插值方案，并区分实测窗口结果与估计的连续时间结果。缺失窗口保留缺失，不填零。

针对用户关心的“升上去再降下来”，同时记录：

- 固定时刻的残余向量 e(t) 及综合幅值 r(t)，包括预先约定的夜间终点。
- 相对首个有效停机后窗口的恢复变化向量 e(t)−e(t_stop_window)，并报告对应时间；该向量的模表示移动距离，不等同于离冷态零点更近。
- 各方向是否跨越冷态零点，以及综合幅值是否先降后升；保留反向漂移。
- 在预先给定容差内连续保持规定时长的恢复时间。容差和持续时长由精度目标与测量能力确定；观察结束仍未达到时报告未恢复，不强填恢复时间。

停止进给到返回测点之间没有有效连续位移测量，不能把首个回测值当作精确的停机瞬间值或宣称测得未观测峰值。

## 7. 两套温度源合并到 Excel：实现条件与字段设计

用户确认 API 当前只保存原始文件，格式待核对。第一阶段按离线合并设计：API 原文件解析＋原温度系统记录解析→保留原始记录→时间对齐→同一 Excel 多工作表。当前没有真实 API 输出样本，不编造文件解析器或设备实时接口。

| 工作表 | 计划内容 |
|---|---|
| `Metadata` | 实验编号、源文件、软件/设备版本、时区、时钟校正、单位和处理配置 |
| `ChannelMap` | `API_T01...` 与 `Legacy_T01...` 的物理位置、环境通道、单位、传感器编号 |
| `API_Raw` | API 原时间、温度与位移原始值、原行号、有效性；G2 故障明确标记 |
| `Legacy_Raw` | 原系统时间与温度，保留缺失、通信状态和原始行号 |
| `Temperature_Aligned` | 统一时轴下的两套温度，各自原采样时刻、时间差、对齐/插值标记 |
| `MeasurementWindows` | 到位状态、稳定窗口、真实有效位移、均值/波动、与温度的关联 |
| `Events` | 运动、停机、回测、冷却/阀门动作、分段与异常时间 |

两套通道使用来源前缀，不能把 API 的 T1（建模手册约定环境温度）与原 ADRC 的 T1（床身）、T5（环境）合并为同一个传感器。

必须确认 API 时间字段是绝对时间、文件内经过时间还是仅采样序号，确认原系统计时是否受丢样影响，记录时钟偏移与可能漂移。不能仅按行号拼接。历史 MATLAB 程序存在按成功样本序号或循环数生成时间的做法，不能当作已验证的逐点实际时间。

离线对齐可使用带容差的最近时刻匹配；如需要温度插值，只对预定长度以内的有效间隙使用并标记，不跨长缺口外推。坏通道保持缺失。面向控制的在线输入必须因果，只使用当前或过去已到达的数据并记录数据年龄；不能使用未来数据插值。

一份 Excel 是分析归档格式，不能证明已实现实时采集。文件落盘周期、软件独占设备、API 实时接口与长时分段均待核对。建议采集期间各源按其可靠方式落盘，合并程序作为唯一写入者生成分析工作簿，避免两个程序同时写同一个 Excel。超出 Excel 行数上限时按实验段分卷，保留索引与原文件。

编写可验证导入程序所需的最小输入：一份 API 真实原始数据、同一时段原温度系统数据、启动与事件时间记录及当前 MATLAB 版本；收到后先确认解析和时间映射，再用真实样例验证合并结果。

## 8. 原控制任务的适配与预测控制路线

本轮读取了仓库中的 ADRC 温控程序与三探头 PID 草稿，以下仅为代码层面发现，不代表现场实际运行版本已确认。

| 项目 | 现有代码行为 | 接入 API 与热位移预测时需要调整 |
|---|---|---|
| 控制目标 | ADRC 用目标温度和实测温度计算六路阀门指令 | 预测模型输出三向热位移；先明确外层位移目标与内层温度/流量目标的关系，不能直接换数值 |
| 通道含义 | ADRC 的 T1 为床身、T5 为环境，部分阀门共用同一温度 | 建立来源/位置映射；API T1 环境定义不能按编号硬接 |
| 采样与离散步长 | 定时器周期及 ADRC h 为 1 s；记录时间取循环次数 | 使用实际时间和状态年龄；回测位移是间歇量，不用旧样本伪装为每秒新反馈 |
| 失效处理 | 温度读取失败时沿用旧值或默认值，部分写入异常未记录 | 缺失/陈旧标记、通信回执、预测不确定度及失效时的保持/回退策略需要明确 |
| 操纵量 | 六阀指令乘 100，限幅 0—6000；代码注释角度、界面百分比存在混用 | 核对仪表定义及实际流量，辨识方向和增益；不能把数值 60 默认为 60% |
| 冷却边界 | ADRC 程序还会按温度条件切换水冷机启停 | 正式八组合需固定实际冷却规则；控制器不能暗中改变既定对照输入 |
| PID 草稿 | 循环中取 `probeVals(1)` 作为控制输入，仍绑定旧三探头系统 | 不是已验证的三维模型点反馈；不能直接接 API 后就宣称实现三维控制 |

建议分阶段建立控制系统：

1. 双温度源离线归档与有效位移样本建立，核对同步和目标点。
2. 按完整实验划分训练与验证，建立预测模型并离线重放。检查跨昼夜、升温/冷却及冷却组合的误差，避免随机打散相邻样本造成信息泄漏。
3. 只显示预测与候选冷却指令，暂以实际测量核对预测方向、时滞及可靠性。
4. 先验证单区域对主要响应的作用，再按动态辨识结果建立多区域协调控制；施加流量/阀门范围、变化率和供水约束。
5. 预测提供两次回测之间的估计，有效回测用于校正模型或状态；记录估计与实测的区别。

真正的“提前控制”需要预测未来一段时间内的位移，并知道不同冷却动作将如何改变它。可使用温度历史、环境温度、运动阶段及负载、过去冷却输入等特征；需要同时验证冷却输入到位移的动态模型。预测时域应覆盖实际冷却时滞及通信/执行延迟，由辨识确定，不预先指定固定算法或增益。

用户上传流程图描述了线性热误差拟合后写入某数控变量进行补偿。该路线输出为数控位置补偿，本研究输出为分区水冷调节，执行机构与时滞不同。可借鉴建模与验证流程，但不能直接沿用图中的 SD43900 变量或写入步骤；当前机床是否支持该变量并无依据。

三维范数适合作为评价或优化目标，只有非负大小，不能单独告诉控制器哪一路阀门应开大。控制模型仍应保留带符号 XYZ 及各输入对三向的影响；冷却并不保证在所有时刻都使三向同时减小。

## 9. 最近的实施优先级

1. 核实 G2 故障及配套修复方式；测量 G4/G5 截面、两层间距和候选端点距离，确定正式三维测量能否成立。
2. 选择新测量位姿，验证 API 静止采集、返回重复性、基准和跨文件保持。
3. 提供 API 原始文件及同期原温度文件，确定离线合并解析规范与软件版本。
4. 完成一轮包含长时停机冷却的无水冷先导，估计回测间隔、最短有效停留和初态恢复判据。
5. 冻结代表性运动程序、八组合冷却水平、基准/夜间策略、主要指标及共同评价时段，开展独立重复。
6. 基于可靠测量依次实施贡献分析、动态辨识、预测验证及控制验证。

本次未改动现场采集/控制程序，未执行 MATLAB 或 API 软件，未操作阀门、机床或数控变量。文中的时长与节拍是先导建议；G2 损坏及 API 原始格式待核对是当前已知约束。
